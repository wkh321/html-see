# 邮箱验证集成指南（用于「函数绘制器 · 我的页面」）

> 目标：在「我的页面」的**用户注册**流程中增加**邮箱验证**，防止无邮箱的批量注册。
> 适用对象：负责维护「我的页面」的 AI / 开发者。
> 前置条件：本指南假设「我的页面」是纯静态网页（GitHub Pages），用户数据存于点鸭数据表（users 表，通过 `dbs-users.js` 操作）。

---

## 一、功能原理

```
用户填邮箱 → 点"获取验证码" → 前端调 Vercel 函数 → QQ邮箱SMTP 发验证码邮件
                                   ↓
用户收到验证码 → 填验证码 → 前端校验通过 → 才允许注册（写入用户数据）
```

- 验证码由服务端（Vercel 函数）生成并**随响应返回**，前端本地保存、本地校验。
- 核心价值：注册者必须**真实拥有**并能收到邮件的邮箱，从而拦截无邮箱的批量注册。
- 无需改动登录流程（仍是用户名 + 密码）。

---

## 二、需要引入的 3 个交付物

| 文件 | 来源 | 用途 |
| --- | --- | --- |
| `qqmail-client.js` | `qqmail-vercel/public/qqmail-client.js` | 前端函数封装（1 个文件，复制进「我的页面」项目） |
| `api/mail.js` + `package.json` + `vercel.json` | `qqmail-vercel/` | 部署到 Vercel 的邮件函数（见部署文档） |
| Vercel 域名 | 部署后获得，形如 `https://xxx.vercel.app` | 配置到 `MailClient.base` |

部署步骤见 `qqmail-vercel/README.md`（Vercel 建项目 → Root Directory 选 `qqmail-vercel` → 配环境变量 `QQ_MAIL_USER` / `QQ_MAIL_PASS` → Deploy）。

> 开发阶段若还没有 Vercel 域名，可先用本地服务联调：`qqmail-server`（已在工作区跑通，端口 3000），把 `MailClient.base` 临时设为 `http://localhost:3000` 即可。

## 四、注册逻辑改造（JS）

### 4.1 引入并配置（页面底部）

```html
<script src="qqmail-client.js"></script>
<script src="dbs-users.js"></script>
<script>
  MailClient.base = 'https://你的项目名.vercel.app'; // Vercel 域名；本地联调填 http://localhost:3000
</script>
```

### 4.2 发送验证码（点击"获取验证码"）

```js
let pendingCode = null;   // 保存本次验证码，用于提交时校验

document.getElementById('btn-code').addEventListener('click', async function () {
  const email = document.getElementById('reg-email').value.trim();
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
    alert('请先填写正确的邮箱');
    return;
  }
  // 节流：防止连点（60 秒内只能发一次，服务端也会限制）
  this.disabled = true;
  setTimeout(() => (this.disabled = false), 60000);

  const r = await MailClient.sendCode({ to: email, digits: 6 });
  if (r.ok) {
    pendingCode = r.code;              // 保存验证码，用于提交时校验
    alert('验证码已发送，请查收邮箱（5分钟内有效）');
  } else {
    alert('发送失败：' + (r.msg || '请稍后再试'));
  }
});
```

### 4.3 提交注册（校验验证码后再写入用户数据）

```js
async function handleRegister(regUsername, regPassword, regEmail, regCode) {
  // 1) 校验验证码（本地比对最近一次发送的验证码）
  if (pendingCode === null) {
    alert('请先获取验证码');
    return false;
  }
  if (!MailClient.verifyCode(regCode)) {
    alert('验证码错误或已失效，请重新获取');
    return false;
  }

  // 2) 校验通过：检查用户名是否已被占用（点鸭 users 表）
  const db = DbsApi.init({ table: 'users' });
  const dup = await db.query({ filter: "id='" + regUsername + "'" });
  if (dup.code === 200 && dup.count > 0) {
    alert('该用户名已被注册');
    return false;
  }

  // 3) 写入用户数据（点鸭 users 表，字段与你的注册逻辑一致）
  const r = await db.insert({
    id: regUsername,          // 用户名
    name: regUsername,
    role: 'user',
    avatar: '',
    stats: '',
    whitelist: '',
    devices: '',
    ip: regEmail             // 用 ip 字段暂存注册邮箱（字段名可自行约定）
  });
  if (r.code === 200) {
    pendingCode = null;      // 验证码一次性使用
    alert('注册成功，请登录');
    return true;
  }
  alert('注册失败：' + r.msg);
  return false;
}
```

> 说明：邮箱字段建议在你数据表已有字段中选一个存储（如示例用 `ip`，或按你的设计新增 `email` 字段）。注册通过后才写入，验证码不随用户数据保存（一次性）。

### 4.4 登录逻辑

登录保持现状（用户名 + 密码）不变。若后续要加「忘记密码」，可用同一套 `sendCode` + `verifyCode` 走邮箱找回。

## 五、注意事项

1. **验证码本地校验的定位**：本方案验证码由服务端生成、前端保存并比对，能满足"必须真实拥有邮箱才能注册"的防批量诉求。若要更强的防刷（如验证码只在服务端、防重放），需后续引入自己的后端，把校验移到服务端。
2. **发送频率限制**：服务端有"同一邮箱 60 秒内只能发一次"限制，前端按钮已加 60 秒节流，请不要去掉。
3. **验证码位数与有效期**：默认 6 位、5 分钟有效，可传 `digits` / `expire` 参数调整。
4. **QQ 邮箱日发信量**：免费 QQ 邮箱约 500 封/天，短时高频发送会触发风控，注册量大的话请控制节奏或改用付费邮箱服务。
5. **用户未收邮件排查**：检查垃圾箱；确认 `QQ_MAIL_USER` / `QQ_MAIL_PASS` 环境变量配置正确；可先用 `curl` 测一次接口（见 `README.md`）。
6. **上线顺序**：Vercel 部署完成并配好域名后，再把 `MailClient.base` 从 `http://localhost:3000` 改成线上域名。
